# Send Messenger — архитектура проекта

## Что представляет собой приложение

Одностраничный сайт Send Messenger на React 18, TypeScript и Vite. Разделы страницы собраны в `src/App.tsx`; отдельного роутера нет. `App` управляет состоянием меню, формы связи, загрузочной заставки и переходами между секциями. Сложные прокрутка и переходы оставлены в существующих компонентах и CSS, чтобы не менять механику анимаций.

## Структура

```text
src/
  App.tsx                       композиция страницы и общее состояние
  main.tsx                      точка входа React
  components/                   секции страницы и интерфейсные компоненты
  styles/index.css              визуальные токены, сетки и анимации
server/
  api.js                        API и раздача production-сборки
  handlers.js                   общие обработчики API для Vite и Node
  handlers.d.ts                 типы общей границы API
public/
  *.webp                        растровые изображения без потерь и иконка сайта
  robots.txt                    правила индексации
```

## Локальная разработка и сборка

- `npm run dev` запускает Vite и подключает те же API-обработчики, что и Node-сервер.
- `npm run build` выполняет проверку TypeScript и собирает сайт в `dist/`.
- `npm run preview` показывает production-сборку через Vite.
- `npm run server` раздаёт `dist/` и обслуживает API. Перед запуском нужна сборка.
- Для production передайте `SITE_URL` с фактическим адресом сайта. Сборка добавит канонический URL и сформирует `sitemap.xml`; без заданного домена проект не публикует выдуманный адрес.

API предоставляет `GET /api/health` и `POST /api/contact`. Форма принимает имя, почту и сообщение. Пересылка уведомлений в Telegram включается переменными окружения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`; без них сервер выводит только номер обращения в журнал. Для production настройте Telegram: сайт не хранит обращения в базе данных.

## Соглашения

- Существующие CSS-классы, стили и motion-последовательности — часть реализации дизайна. Рефакторинг компонентов не должен менять их поведение без отдельного запроса.
- Имена секций и доступные якоря должны совпадать с навигацией `SiteHeader` и `MenuOverlay`.
- Растровые изображения хранятся в lossless WebP; повторно используемые иконки не дублируются.
- Не добавляйте проекту чужие продуктовые тексты, географию или домены. Метаданные должны описывать Send Messenger.
